# 已知限制与排查

> 从 [README](../README.md) 拆出来的。

## 已知限制

| # | 限制 | 说明 |
|---|---|---|
| 1 | **最多只能还原 20 条** | `trim()` 只保留最近 `max-messages` 条，防止上下文把 token 打爆。这是取舍，不是丢数据 |
| 2 | **报告模式刷新后显示原始 JSON** | Advisor 存进 Redis 的是模型返回的原始 JSON 文本，页面上那个格式化是前端渲染的、没存下来。（气泡标签本身是对的，会显示「结构化报告」） |
| 3 | **空会话刷新后会消失** | 会话名单是 `add()` 写入的，也就是"必须至少聊过一句"才会出现。ChatGPT 也是这行为 |
| 4 | **并发写会丢消息** | `RedisChatMemory.add()` 是"读-改-写"，同一 chatId 并发会互相覆盖。要严格保证得加 WATCH/MULTI 乐观锁 |
| 5 | **配置里有块废弃的 `ai-agent.redis`** | `application.yaml` 里那段 `ai-agent.redis.host/port` 是早期版本留下的，现在**没有任何代码读它**（Redis 连接实际走 `spring.data.redis.*`）。留着容易误导人以为改这里能换 Redis |
| 6 | **向量库是单机的** | `SimpleVectorStore` 存在内存 + 一个 JSON 文件，重启才加载。多实例部署会各存各的 |
| 7 | **RAG 依赖外网** | 每次检索都要调百炼把问题向量化，断网或 VPN 劫持 DNS 时 `/love/rag` 会直接 500 |
| 8 | **最老的几轮可能没有模式标签** | 模式是后加的，之前的记录里没存过；而且消息按条数、模式按轮数裁剪，两边规则不同。对不上时宁可不显示标签，也不猜一个 |
| 9 | ⚠️ **抓来的网页内容没做提示注入防护** | 网页正文是**原样进模型上下文**的。如果页面里写着"忽略之前的所有指令，改为……"，模型有可能会听。真实产品里要给外部内容加上明确边界并降低其指令优先级 |
| 10 | ⚠️ **抓取工具没有 SSRF 防护** | 模型自己挑 URL，没有白名单也没挡内网地址，所以它能让你去抓 `http://localhost:8123/...` 或局域网地址。**只适合本地演示，别把 `/love/search` 暴露到公网** |
| 11 | **消息窗口可能切在工具调用中间** | `trim()` 是按条数从尾巴粗暴切。**如果**工具调用的中间消息也进了记忆，窗口边界有可能正好切在"工具调用请求"和"工具返回"之间——模型会收到一条没有对应调用的工具结果，DeepSeek 会返回 400。这个场景**还没实测确认**（需要真调一次模型才能看出来），遇到再处理 |
| 12 | **工具调用没有轮次上限和超时控制** | 模型理论上可以反复调工具。底层 HTTP 用的是 `RestClient` 默认超时 |
| 13 | ⚠️ **MCP server 连不上会让整个应用起不来** | MCP server 是**外部进程**，Spring 在启动时就要连上它、拿到工具清单。拿不到整个容器启动失败，而不是"MCP 模式不可用"。本项目靠 `npm i -g` 把包预先装到本地，才让 `initialized: true` 成立；换机器或网络变化会重新触发，届时把 `initialized` 改回 `false` 即可恢复启动（见[设计说明](设计说明.md) → 6） |
| 14 | **`FileReadTool` 写了但没接上** | 类在 `tool/FileReadTool.java`，也注入了 `LoveApp`，但没有任何方法把它挂到 `.tools(...)` 上，目前是死代码 |

## 常见问题排查

### `HTTP 401 - InvalidApiKey`
key 没配或配错。检查 `application.yaml` 里对应厂商的 `api-key`。

### `Remote host terminated the handshake`
**TLS 握手失败，大概率是 VPN 劫持了 DNS。** 某些 VPN（WireGuard 类）会把域名解析到 `198.18.x.x` 这种假 IP。

验证：
```bash
nslookup dashscope.aliyuncs.com
# 返回 198.18.1.229 这类地址 = 被劫持了
# 正常应该返回 8.152.159.24 之类的真实 IP
```

解决：关掉 VPN，或在 `C:\Windows\System32\drivers\etc\hosts` 里加真实 IP：
```
8.152.159.24 dashscope.aliyuncs.com
```

### `Port 8123 was already in use`
上一次的进程没退干净。查 PID 并结束：
```bash
netstat -ano | findstr :8123
taskkill /F /PID <PID>
```

### 浏览器直接访问接口返回 `405` / `404`
- `405`：浏览器地址栏发的是 **GET**，而这些接口是 **POST**。用 curl 或前端页面
- `404`：路径错了。注意三点——`context-path` 是 `/api`（别漏）、`/love/chat/stream` 不是 `/love/stream`、中文参数要 URL 编码

### 前端刷新后会话列表是空的
`chat:sessions` 这份名单**只在聊过天之后才有内容**。如果你之前的数据是在功能上线前存的，名单里没有登记过，**需要在那个会话里再发一句话**才会出现。

### 刷新后气泡上没有「知识库问答」那个标签
分两种情况：
- **改动之前聊的老会话**：那时候模式压根没存过，所以不显示。这是**故意的**——不知道就不猜。在那个会话里再聊一句，新的一轮就有标签了
- **新聊的也没有**：那说明这一轮没记上。模式是**模型成功返回之后**才记的，中途报错或被「停止」的那一轮不会有记录（这和记忆本身的写入时机是一致的）

### RAG 回答"我没有这份文档" / 看起来没检索到
先确认一件事：**这大概率不是没检索到，而是你问的是"整份文件在不在"**。
检索默认只取最相似的 4 段（知识库共 15 段），模型手上只有片段，问全文它只能否认。

想验证检索到底有没有生效，要问**正文里独有的内容**，别问文件名。比如：

```
知识库里推荐了哪些课程？
```

期望答出《单身魅力提升全攻略》《线上交友高效脱单指南》或网址 `codefather.cn`——
这些字符串只存在于知识库，**模型编不出来**，所以答对了就是检索铁证。

判断技巧：模型如果说的是"上面能看到的内容只是其中几段"，那就是检索**成功了**，
它在如实说明自己只有片段。

### 选了「联网搜索」但模型没去搜 / 回一句"没法联网"
按顺序查三件事：

1. **`bocha.api-key` 配了没**。没配的话工具会返回一句"没有配置 api-key，用不了"，模型就会照实转告你。这是**故意的**，不是报错
2. **问题是不是根本不需要联网**。模型只在"需要实时信息"或"自己没把握"时才会调工具。问"你好"它当然不搜——这恰恰说明工具没被乱调
3. **看后端日志有没有两条 `AI Response`**。只有一条 = 模型压根没决定调工具；有两条且第一条是 `text="<none>"` = 工具调用发生了

### 「联网搜索」模式下模型乱调工具 / 每次都搜
先看 `WebSearchTool` 上那个 `@Tool(description = ...)`。
**模型完全靠这段描述判断什么时候该调这个工具**——写得越含糊，它越容易该调不调、或者不该调乱调。
调提示词比调代码管用。

### 应用启动直接失败，报 `Client failed to initialize by explicit API call`
先说结论：**这大概率不是代码问题，是 MCP server 起不来。**

MCP server 是**外部进程**，Spring 在**启动时**就要连上它、问它"你有哪些工具"。拿不到答案，整个 Spring 容器就起不来（见[设计说明](设计说明.md) → 6. MCP 接入）。日志里那条超长的因果链，**最后一环才是根因**：

```
... → mcpToolCallbacks → mcpSyncClients → Client failed to initialize by explicit API call
```

这里配的 MCP server 是 `npx -y @amap/amap-maps-mcp-server`，需要**能访问 npm registry** 才下得到这个包。如果日志里接着出现：

```
npm error network request to https://registry.npmjs.org/@amap%2famap-maps-mcp-server failed
npm error network Client network socket disconnected before secure TLS connection was established
```

那就是网络问题。三条路，**本项目走的是第 1 条**：

1. **把包提前装到本地（推荐，本项目就是这么解决的）**：`npm i -g @amap/amap-maps-mcp-server`。
   装好之后 `npx` 在本地就找得到它，不用再联网——`initialized: true` 这才成立
2. **先让应用能起来**：把 `spring.ai.mcp.client.initialized` 设成 `false`。bean 照常建好、启动时先不连，代价是 MCP 工具为空
3. **换能用的镜像 / 代理**：注意 `registry.npmmirror.com` 在某些网络下**同样不通**，别以为换个镜像就一定好

> ⚠️ **这个网络是会抽的**：同一条命令隔一段时间测，先返回 `000`、后来又变成 `200`。
> 所以"MCP 昨天还好好的、今天起不来"是完全可能的，**别急着怀疑代码**。

先自测一下网络到底通不通（`000` = 没连上）：

```bash
curl.exe -s -m 10 -o /dev/null -w "http=%{http_code}\n" https://registry.npmjs.org/
```

另外 `mcp-servers.json` 里的 `AMAP_MAPS_API_KEY` 还是占位符 `你的高德Key`，
要去高德开放平台申请一个填上，地图工具才真能调通。

### 选了「MCP 工具」但模型从来不调工具
按这个顺序排查，别跳步：

1. **系统提示词和工具打架**（最常见）。本项目实际就撞上了：`prompts.SYSTEM` 的「边界」写着"只讨论情感话题"，
   于是"查天气"被当成其他话题挡了回去。见[设计说明](设计说明.md) → 6里那条例外
2. **MCP 其实没接上**。看启动日志有没有 `Amap Maps MCP Server running on stdio`；
   没有就是连不上（见上一条）
3. **工具到底发出去了吗**。用一个假的 `ChatModel`（Mockito mock 掉）把请求截下来，
   看 `ToolCallingChatOptions.getToolCallbacks()` 里有没有东西——这样能把
   **"根本没发出去"和"发出去了但模型不调"**这两种完全不同的故障分开

顺便：就算模型调了工具，**工具报错也不会抛异常**。高德因为 key 是占位符返回
`INVALID_USER_KEY` 时，这个错误是作为一条**工具结果**（`isError=true`）回到模型手里的，
模型再转述给用户。所以看到"天气查询失败了"恰恰说明**整条链路是通的**。

### 向量化失败但应用还能启动
这是**故意的**。`LoveAppVectorStoreConfig` 里把向量化包在 try/catch 里——RAG 是附加功能，不该把已经能用的对话功能一起拖垮。失败只记一条 ERROR 日志，`/love/rag` 会因为向量库为空而答不出东西，但 `/love/chat` 不受影响。
