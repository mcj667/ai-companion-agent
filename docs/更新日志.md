# 更新日志

### 2026-10-11
- **API Key 改成环境变量**：`application.yaml` 里三个 key 全部换成 `${...}` 占位符，明文 key 从项目里彻底移除。三个 key 的"缺省行为"是**刻意设计成不一样的**：
  - `DEEPSEEK_API_KEY` —— **必填**，没设时应用直接启动失败并报 `Could not resolve placeholder`。对话是核心功能，没有 key 整个应用就没意义，早失败、报错直指原因，比"启动成功了但每次对话都 401"清楚得多
  - `DASHSCOPE_API_KEY` —— 缺省值 `not-configured`（**不是留空**：留空会让 DashScope 的自动配置校验失败、整个 Spring 上下文起不来）。`not-configured` 正是 `LoveAppVectorStoreConfig.PLACEHOLDER_API_KEY` 认的"没配"标记，会走优雅降级，RAG 退化成普通对话
  - `BOCHA_API_KEY` —— 缺省为空，联网搜索模式返回一句"没有配置 api-key，用不了"，模型顺势如实告诉用户
- README「快速开始 → 1」重写：改成环境变量配置说明（IDEA 运行配置 / `setx` 两种方式 + 三个 key 缺失时各自会怎样）
- 已知限制：删掉「API Key 是明文」那条（已修复），换成「配置里有块废弃的 `ai-agent.redis`」

### 2026-10-10
- 新增会话历史能力：`GET /love/sessions`、`GET /love/history`、`DELETE /love/sessions`
- 新增 `ChatSessionRegistry`，用 Redis ZSet 维护会话名单
- 新增 `ChatHistoryService`、`MessageVO`、`SessionVO`
- 前端移除 localStorage 存消息，改为服务端为唯一数据源
- 前端新增会话列表加载态
- **修 bug**：刷新页面后，RAG / 流式 / 报告的气泡全被标成「普通对话」。根因是 `ChatHistoryService` 把 `mode` 写死成了 `"chat"`——模式在整条链路上压根没被采集过，因为写记忆的 Advisor 只知道消息内容、不知道调的是哪个接口
- 新增 `ChatModeRegistry` + `ChatMode`：在控制器里按轮记录模式，存成 Redis List；`LTRIM` 只留最近若干轮，TTL 和 `chat:memory` 同步
- `ChatHistoryService.resolveModes()`：从最新一条往前对齐模式，对不上的轮次返回 `null`，前端不显示标签
- 流式接口用 `doOnComplete` 挂记录（不是 `doFinally`），和 `MessageChatMemoryAdvisor` 写记忆的时机严格一致，中途「停止」或报错两边都不记
- 新增 12 个测试（6 个对齐算法单元测试 + 6 个 `ChatModeRegistry` 真实 Redis 集成测试）
- **修 RAG 措辞问题**：默认模板只给模型正文、不说这是"片段"，导致一问"你知道《某文档》吗"就回"我没有这份文档"，看起来像检索失败。改成自定义模板 `prompts.RAG_ANSWER`，明说这是知识库里找到的相关内容、不是全文
- 新增 `RagPromptTemplateTest`，钉住占位符 `{question_answer_context}`（写错会让每次 RAG 提问都抛异常）
- README 补上「怎么正确验证 RAG 检索」的排查方法
- **新增工具调用**：`POST /love/search` + 前端第五个模式「联网搜索」。模型自己决定要不要调 `WebSearchTool.webSearch`（博查 BochaAI）和 `WebPageTool.fetchWebPage`（jsoup 抓正文、截断到 3000 字）
- 新增 `ChatMode.SEARCH`，直接复用前面已经做好的模式记录 + 气泡标签那一套——刷新后标签不丢
- **修工具调用顺带带出来的两处错位**：一轮里会多出「我要调工具」（没有正文）和「工具返回」（`TOOL` 类型）两条消息。前者会让 `resolveModes()` 多吃掉一个模式、导致标签整体串位；后者会被渲染成一个几千字的搜索结果气泡。现在只让**有正文的** assistant 消费模式，并在历史接口里跳过 `TOOL` 消息
- 工具方法一律不抛异常，失败也当成一条"结果"返回给模型（抛出去会让整个对话请求 500）
- 新增 8 个测试（`WebSearchToolTest` 4 + `WebPageToolTest` 3 + `ChatHistoryServiceTest` 加 1），都是不联网、不花钱的纯单元测试
- README 新增「核心设计 → 5. 工具调用」，讲清「模型只是说、执行在本地、一轮两次模型调用」，并**如实记下没做的安全防护**（提示注入、SSRF）

- 实测确认接上（不只是"配对了"）：启动日志出现 `Amap Maps MCP Server running on stdio` + 协议握手成功，`ToolCallbackProvider` 里拿到 **12 个** `maps_*` 工具（`maps_geo`、`maps_weather`、`maps_direction_driving` …）——**这些方法项目里一行代码都没有**
- 记下这个网络**是会抽的**：同一条 curl 先返回 `000`、过一会儿又返回 `200`。以后遇到"MCP 昨天还好好的"，先怀疑网络、别怀疑代码

- **发现并修掉一个真问题：系统提示词把工具"锁死"了**。12 个工具确实发给了模型（用 Mockito 假 `ChatModel` 截住请求验证过），但模型一次都不调——因为 `prompts.SYSTEM` 的「边界」写着"只讨论情感话题"，把"查天气"当成其他话题挡回去了。在边界里加了一条例外，同一句话从"这属于其他话题"变成"告诉我具体日期，我马上帮你查"
- 记下排查顺序：**先确认工具发出去没有，再看提示词有没有和工具冲突**。工具接得对 ≠ 模型会用
